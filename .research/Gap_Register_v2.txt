3. G1 — Right to Erasure in Vector Stores
Namespace-per-tenant satisfies tenant separation but not an individual's Article 17 request, and the standard deletion mechanism makes this worse than it looks.

The finding
Vector databases typically implement deletion as a metadata-level soft delete by design, to preserve index performance — the embedding remains physically unchanged on disk. Article 17 requires verifiable erasure rather than functional deletion, and an API returning no records is ambiguous between deletion and suppression. Under EDPB Guidelines 05/2019 erasure must be verifiable and irreversible and must extend to all storage layers including backup snapshots; cryptographic erasure was the only tested approach that eliminated recovery entirely.

	•	Crypto-shred. Encrypt per data subject and erase by destroying the key. This is the mechanism that survives soft deletion and produces auditable evidence.
	•	Map every derived artefact. Cached summaries and pre-computed responses must also be invalidated, so the semantic cache and agent memory are in scope alongside the vector store, the embedding pipeline and any derived graph. Document the map in the DPIA under Art.35.
	•	Run erasure as a durable workflow, not an API call: it spans systems, needs retries and an audit trail, and may need human review for legal holds. This is Component 9 work.
	•	Test it. Delete a synthetic subject, then attempt recovery from raw storage and every cache. Add to the definition of done.
Timing: the EDPB began its 2026 Coordinated Enforcement Action on 19 March 2026 with 25 DPAs auditing transparency obligations.
4. G2 — SLOs and Error Budgets
Traditional SLOs assume a deterministic contract; identical inputs can produce different but plausibly correct outputs, or quiet failures that never surface as errors. When an agent fails the observability stack is frequently silent — 200, normal latency, zero error rate.

Note that across 14 models over 18 months of releases, accuracy improved steadily while reliability improved only modestly, so consistency needs its own SLI.
5. G3 — Test Strategy
Conventional testing treats flakiness as a defect to eliminate; for agents non-determinism is a property of the system under test. Flaky AI tests usually indicate real non-determinism, prompt sensitivity or model drift.

Why single-run testing misleads
Under the τ-bench pass^k estimator one evaluated agent fell from pass₁ = 29.6% to pass₅ = 8.0% — only 8% of tasks succeeded on all five trials — and the failures were silent, with no tool error marking a violating run. Resampling is not a fix, because in deployment the agent runs once.

6. G4 — Model Deprecation

The notice window is shorter than most migration plans
Across 208 tracked records from five providers, median notice runs roughly 63–91 days by provider, with observed ranges as low as zero days. As of late August 2026, 29 of 53 scheduled retirements fell within the following 90 days. Plan capacity around the worst case.

	•	Pin snapshots, never aliases — a call site on a rolling alias cannot answer which side of a retirement date it sits on. The prompt registry becomes the model inventory.
	•	Run n+1 evals continuously, not on day 28 of a 60-day window.
	•	Expect silent regression: repointing keeps returning 200s while tool-call formatting shifts, JSON adherence loosens, refusal boundaries move and verbosity changes token budgets.
	•	Negotiate minimum notice into contracts — 30–60 days for planned deprecations; "commercially reasonable notice" is not a commitment.
7. G5 / G6 — Incident Response and Reporting

Detection is the failure point, not response
Mean time to detect across available agent-incident case studies is closer to 14 days than 4 hours, because agents act in single transactions that look identical to authorised activity in the audit log. Traditional software fails loudly; agents fail plausibly.

	•	Detection panels first, kill switch second. A 50× cost spike within an hour with flat latency is a detectable signature; so is tool-call success collapsing with a flat error rate.
	•	Rollback profile per action class — database writes, external API calls, payments, notifications, permission changes. Where rollback is impossible the runbook names the substitute: compensating action, customer notification, or regulatory disclosure.
	•	Containment precedes root cause; rollback is the default after a deploy-linked incident, and cleanup is never combined with it. Recover in tranches with verification between steps.
	•	Every incident becomes a regression test, closing the loop into Component 14.

Timelines run from awareness, and an incomplete initial report is expressly permitted to meet them. Two operational consequences the runbook must encode. First, the no-alteration rule: the provider must not perform any investigation that alters the system in a way which may affect subsequent evaluation before informing the authorities. That directly conflicts with the instinct to hot-fix, so the runbook needs an evidence-preservation step ahead of remediation. Second, authorities may order measures within seven days of the report, and non-compliance carries fines up to €15 million or 3% of worldwide turnover.
Assign the reportability decision to a named role now. It cannot be made for the first time during an incident with a two-day clock running.
8. G7 — Certification Path
The AICPA has issued no authoritative AI-specific SOC 2 standard; auditors apply the 2017 Trust Services Criteria plus a practitioner overlay, increasingly tested against the OWASP LLM Top 10, with prompt injection cited in nearly every 2026 audit evidence request.
Scope Security plus Confidentiality at minimum, add Availability when SLAs are contractual, add Privacy whenever personal data is processed. ISO/IEC 42001 typically follows in year two or three and is worth adding when buyers are European or when building toward AI Act conformity.
The architectural consequence: AI in production expands SOC 2 scope to models, training data and automated decision-making, and expands evidentiary requirements to auditable records of production execution. That is the same record required by Article 73 reporting, Article 17 erasure evidence, and AI Act deployer logging — four obligations satisfied by one well-designed execution log.

10. G9 — Disaster Recovery
Set tiered objectives rather than one number for the estate. The workflow engine is the strongest part of the position: workflow state writes are synchronously replicated across three availability zones before acknowledgement, giving zero RPO for an AZ failure, with multi-region replication targeting sub-one-minute RPO and automatic conflict resolution after failover.

Where DR actually breaks
Most teams have the data side covered — backups run, RPO is tested. RTO breaks down at the configuration layer: IAM, networking and service settings rebuilt manually under pressure mid-outage. The gap between documented and actual infrastructure state widens further when AI agents are making production changes.

Capture infrastructure configuration continuously so "last known good" is a real target, and include the configuration restore step in DR tests.
11. G10 — Red-Team Programme
Cadence is the finding. Adversarial testing must be continuous and automatable, because a new model version, a changed system prompt or an added tool can reopen a previously closed vulnerability. Quarterly is the floor for a serious programme, not the design point.
Map findings to four standards so results are portable into procurement and audit: the OWASP Top 10 for Agentic Applications (ASI01–ASI10) for the agent layer, the OWASP LLM Top 10 for the model layer, MITRE ATLAS for adversary tactics, and NIST AI RMF for governance scaffolding. Documented OWASP coverage is increasingly a requirement in enterprise sales cycles.

Calibrate expectations
Prompt injection maps to six of ten agentic categories — treating it as one checklist item underweights it. In a March 2026 exercise run by NIST's AI safety centre with Gray Swan and the UK AI Security Institute, over 250,000 attempts from 400+ participants found at least one successful attack against all 13 target frontier models in agentic scenarios. The programme's goal is bounded blast radius and fast detection, not a clean scorecard.
12. G11 — Secrets Management
The framing shift: rotation does not change the model. The workload still depends on a reusable secret, so if it leaks the attacker has something usable. The stronger pattern authenticates the workload by an identity it already has — cloud identity, Kubernetes identity, OIDC token, certificate — and mints a short-lived credential on demand.
Where secretless is not possible, tier the rotation: roughly 180 days for long-lived externally-issued keys with an access review at each rotation, 30–90 days for service-to-service tokens because they carry broad scopes and are widely cached, and no rotation policy for workload identities with sub-24-hour TTL since they rotate on every use. Use the dual-credential window pattern and canary the rotation before production.
Webhook signing secrets deserve specific attention because rotation interacts with in-flight verification: publish the key ID in the signature header, accept both keys during the overlap window, and only then retire the old one.
The real failure is non-remediation, not mechanics. 64% of secrets confirmed valid in 2022 were still exploitable four years later — the gap between having a policy and executing it across the full inventory. Track last-rotation date as a metric and alert when it exceeds policy.
13. G12 — Data Residency and Subprocessors
Zero data retention is contractual and must be applied for, not assumed. Default abuse-monitoring log retention of up to 30 days is what trips most GDPR reviews, and removing it requires an active ZDR arrangement.
Record six attributes separately for every provider, because they are independent and a single "EU" claim conflates them: storage location, processing location, retention period, training use, subprocessor list, and governing jurisdiction. Regional processing, EU data-boundary deployments, EU-default platforms and self-hosting are the available shapes, with self-hosting giving the strongest control and the highest operational burden.

The subprocessor trap
AI vendors are stacking subprocessors faster than legacy SaaS. One documented case: a major model provider became a subprocessor to a widely-used productivity suite in January 2026 and was explicitly out of EU Data Boundary scope for that route, surprising buyers who assumed the suite meant EU-only processing. Re-read the DPA on every major product change, not once at signature.

Architectural consequence for the gateway: residency is a routing constraint, not a configuration flag. Tenant region must be a first-class routing input in Component 2, and the fallback chain must not silently route an EU tenant to a non-EU provider during a failover. That is a plausible failure mode of the current design and should be an explicit test case.
14. G13 — Unit Economics

The margin structure is different from SaaS and should be planned that way
ICONIQ 2026 data puts average AI product gross margin at 52% against the 80% mature-SaaS benchmark, with inference consuming roughly 23% of revenue at scaling-stage AI B2B companies. Pricing a flat subscription against heavy agentic users goes underwater; the market has converged on usage and hybrid structures precisely because they keep a cost-following component in the price.

	•	Price on resolution, not containment. Containment is easy to inflate and disconnected from value — a contained-but-unsolved task returns as a second contact at full human price, or as churn.
	•	Divide by the realistic resolution rate before comparing anything. At a 60% resolution rate a $2.00 per-conversation fee is an effective $3.33 per resolution.
	•	Know your marginal floor. Self-built stacks can reach roughly $0.15–$0.30 marginal per task at scale, which is the number that justifies the platform investment in the Implementation Plan against buying a per-resolution vendor.
	•	Make cost per resolved interaction an SLI (see G2) so a routing change that improves quality while destroying margin is visible immediately rather than at month end.
15. G14 — API Versioning
URL path versioning for the public API: it is debuggable, CDN-cacheable, and unambiguous in logs. Additive changes — new fields, new endpoints, new optional parameters — never bump the version.
Signal deprecation in-band. Use the Deprecation header (RFC 9745, Standards Track, March 2025) carrying the date the version was deprecated, and the Sunset header (RFC 8594) carrying the date requests begin returning 410 Gone, with a Link header pointing at the successor version and migration guide. These give client tooling a machine-readable signal instead of a changelog entry someone may never read.
Notice period: 6–12 months for a public API version, with changelogs and migration guides published at announcement. Alert when deprecated-version traffic has not decreased 30 days after deprecation, so high-volume consumers get direct outreach well before sunset.
Three version planes, kept distinct: the public API version, the webhook payload version, and the workflow-definition version. They have different consumers and different lifetimes — a workflow definition may need to outlive the API version that started it, which is the interaction the Engineering Standards flagged but did not resolve.
16. G15 — Agent Memory
Long-term memory is the primary target of poisoning attacks, and it divides into factual memory (preferences, policies) and experience memory (past actions and outcomes).

Why this is a distinct threat, not a variant of prompt injection
Memory poisoning creates persistent compromise, temporally decoupling injection from damage: the injection happens in one session, the damage in another, after the original context is discarded. Traditional monitoring sees nothing suspicious at any single point in time. OWASP added ASI06 (Memory & Context Poisoning) to the Top 10 for Agentic Applications 2026.

Structural defences, in order of effect:
	•	A conservative, scope-limited write policy defining exactly what the agent may store — this alone produced markedly lower attack success in comparative testing, and is the simplest first line of defence.
	•	Source isolation, so untrusted external content is never treated as equivalent to authenticated user input during a write decision.
	•	Write-path provenance on every entry, enabling source-aware retrieval that demotes or quarantines untrusted origins.
	•	A compaction filter distinguishing trusted from untrusted content, so adversarial payloads do not survive summarisation into persistent memory. This connects directly to the constraint-pinning requirement already in the plan.
Governance requirements: selective retention, secure storage, user-controlled deletion and transparent auditing of what is remembered and forgotten — most production systems provide limited tooling for any of these. User-controlled deletion is the direct dependency on G1. Two open problems to accept rather than solve: cross-session identity resolution (the memory model assumes a stable user ID, which anonymous and multi-device sessions break) and staleness in high-relevance memories, where a confidently-retrieved fact about a user becomes confidently wrong.
17. G17 — Human Oversight

The volume arithmetic
Fifty agents at twenty tool calls per hour produce 1,000 approval-eligible events per hour. Routing even 10% to human review consumes more than three full-time equivalents doing nothing but rubber-stamping. An approval gate without a staffing model is not oversight; it is a queue that will be cleared as fast as possible.

The evidence on review quality is worse than intuition suggests. In a study of 27 radiologists reviewing against AI suggestions, accuracy when the AI was wrong fell from roughly 80% to under 20% for inexperienced readers — and from 82% to 45.5% for those with 15+ years' experience. Tenure does not inoculate against automation bias.
A counterintuitive finding that affects the Design Standards. Reviewers given clear explanations of the AI's reasoning deferred more heavily to its recommendations — better explainability can substitute for oversight rather than support it. This does not argue against the transparency requirements in Section 10 of the Design Standards, but it does mean explanation quality cannot be treated as evidence that oversight is working. Measure the outcome, not the affordance.

Recommended design:
	•	Risk-tiered decision lanes with SLAs — a seconds-scale lane for low-risk actions, minutes for sensitive data access, longer for financial actions. On timeout, fail safe to denied and capture partial context for audit.
	•	Volume caps per reviewer per day, explicit rejection criteria in training, and a feedback loop that closes on overrides.
	•	Instrument the rubber-stamp rate as a governance metric. A reviewer approving 99% of decisions at under ten seconds average review time is clicking, not reviewing. This number belongs on the same dashboard as the SLOs.
	•	Move oversight earlier where possible. Defining in advance what an agent may do autonomously, under what conditions, scales better than pausing at execution time with limited context and time pressure — which is the graduated-autonomy model already in the Design Standards, now with a staffing rationale behind it.
18. G18 — Rollout and GA Criteria
Four stages, each answering a different question: shadow (does it behave?), canary (does it behave on real traffic?), percentage (does it behave at volume?), full. Skipping one ships an incident.

A documented failure worth designing against
A prompt edit passed a 1% canary on green dashboards and was promoted to 25%. Twelve hours later an enterprise tenant reported a subtly broken tool-call schema on a sub-route the regression suite never hit — mean groundedness held at 0.91 while production groundedness on affected traffic sat at 0.62. The semantic cache kept serving the bad answer for forty minutes after rollback. Cache invalidation must be part of the rollback procedure, not a separate cleanup.

	•	Every shadow trace needs an evaluator subscribed on ingest. Otherwise you accumulate storage cost and learn nothing — if scoring is not wired, do not store the shadow.
	•	Rollback conditions are written rules evaluated on a rolling window, not dashboard impressions, and they are wired into config before traffic flips.
	•	Hash on user or session ID for routing stability. Without it a user mid-conversation hits different versions across turns and gets incoherent context.
	•	Stage schedule: 5% → 15% → 40% → 80% → 100%, holding 7–14 days of stable production data before each expansion; 6–12 weeks end-to-end is typical for a moderately complex agent.
	•	Retain shadow after GA at a small percentage as ongoing drift detection.
19. G19, G20, G23, G25 — Organisational Gaps
These four require decisions rather than research; the findings above determine what the decisions must cover.

Gap
Required position
G19 Ownership
A named person per component, not a role. Three roles must be pre-assigned before launch: incident commander, the Article 73 reportability decision-maker, and the operator holding emergency-halt authority without waiting for approval.
G20 Vendor exit
An abstraction layer is not an exit plan. Test against an alternative provider on a recurring schedule, keep prompts in version control rather than provider-specific tooling, and set a concentration limit per provider. The rehearsal is the deliverable.
G23 Analytics
Separate from observability. The metrics that matter here are product-specific: correction rate, override rate, approval latency, rubber-stamp rate, and resolution versus containment. Corrections are also the eval feedback loop, so this is not purely a reporting concern.
G25 Documentation
A runbook index that an on-call engineer can navigate at 3am, and an onboarding path. Treat docs as a release artefact gated in CI, since a runbook that lags the system is worse than none.

21. What This Changes
Three findings cut across the whole programme and should change the plan rather than sit in a register.

	•	Foundation F3 is the highest-leverage component and is still one row in a table. Erasure evidence (G1), Article 73 reporting (G6), SOC 2 evidence (G7), memory provenance (G15) and AI Act deployer logging all resolve to one capability: a complete, queryable, tamper-evident record of what the agent did, with what data, on whose behalf. Specify it properly before Phase 1 begins.
	•	Residency is a routing constraint (G12), not a configuration flag. Component 2's fallback chain can currently route an EU tenant to a non-EU provider during failover. Add tenant region as a routing input and make it a test case.
	•	Cache invalidation belongs in the rollback path (G18). A semantic cache that outlives a rollback extends every incident. This is a further argument for keeping Component 7 conditional.

Four documents remain to be written, and the research above is the input for each: Data Protection & Retention (G1, G12, G15), Reliability & Operations (G2, G5, G6, G9, G19), Test & Security Assurance (G3, G10, G18), and Compliance & Certification (G7, G14, G24).
